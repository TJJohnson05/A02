**Branch** - A parallel version of a repository. It is contained within the repository but does not affect the primary branch, this allows you to work freely and independently without disrupting the live or used version. After making said changes in the branch, you can then merge said changes to the live version of the repository, essentially allowing you to publish your changes.

**Clone** - A copy of a repository that lives on your computer instead of on a separate website or platform somewhere. When making a clone, you can make changes in your preferred editor and use git to track your changes without having to be online. The repository you cloned is still connected to the remote version so that you can push your local changes allowing you to keep them synchronized while you are online. 

**Commit** - A commit or revision is an individual change to a file or group of files. When you make a commit to save your work, git creates a unique ID allowing you to track, monitor and potentially go back to previous commits along with being able to see who made said changes. Commits usually contain brief descriptions of what changes or revisions have been made.

**Fetch** - When using the command git fetch, you’re adding changes from the remote repository from your local working branch without committing them. Unlike git pull, fetching allows you to review changes before actually committing them to your local branch. 

**GIT** - An open source program used for tracking changes in text files. Originally written by the author of the linux operating system and is the core program used by GitHub.

**Github** - A platform created for building software. Used to store, share and work on software projects all built using a program called git. 
Merge - Merging takes the changes from one branch and combines it to another. This will often show up as a pull request or can be done through the command line with git installed.

**Merge Conflict** - A difference that occurs when merging two different branches together. Essentially changes are being made in the same line or file. Before the files can be merged, the merge conflict must be solved.

**Push** - To push means to send your committed changes to a remote repository on github.com. For example, if you change something locally, you can push those changes so that others can interact with them 

**Pull** - Refers to when you are fetching changes from a repository and merging them to another repository. For example if someone is working on the same repository and has made changes, you would want to pull those existing changes so that the file is up to date. 

**Remote** - The version of a repository that is hosted on a server. Remote versions can be connected to local clones so that changes can be synced. 

**Repository** - The most basic element of GitHub. Think of a project folder, that contains all the projects files and stores each files revisions in a sort of history book. Repositories can have multiple collaborators and can be private or public.
